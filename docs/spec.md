# 仕様書(spec)

本ドキュメントは、プロジェクト指示のうち要件部分(目的・利用フロー・機能1・機能2・LINE規格・UI要件)を整理したもの。
仕様を変更した場合は、本ファイルとREADME.mdを同時に更新すること。

## 1. 目的

LINEスタンプ(静止画24個セット)の制作を助けるブラウザツール。

1. 参照キャラクター画像1枚と、24個分の「セリフ・状況」から、ChatGPT画像生成に渡す日本語プロンプトを作る(機能1)。
2. ChatGPTが生成した「24個のスタンプが1枚に並んだシート画像」(6列×4行)を自動検出で24枚に切り出し、微調整し、LINEスタンプ規格のPNG(透過)にしてZIPで書き出す(機能2)。

画像生成そのものはツール内では行わない。プロンプトを作るだけで、生成はユーザーがChatGPT上で行う。

## 2. 利用フロー

1. 【タブ①】参照画像を登録し、24行の表に「セリフ・状況」を入力する。
2. 「プロンプトを生成」→「コピー」。
3. ChatGPTに参照画像を添付し、コピーしたプロンプトを貼って生成する。
4. 生成された1枚のシート画像をダウンロードする。
5. 【タブ②ステップA】シート画像をアップロードし(複数回生成した場合は複数枚まとめて)、自動検出→枠を微調整→「この枠で確定」。
6. 【タブ②ステップB】カード一覧でプレビューを確認しながら、選択中の1枚を左パネルで調整。複数シートがある場合は、番号ごとに採用元シートを選べる。
7. 「ZIPで書き出し」→ 01.png〜24.png・main.png・tab.pngが入ったZIPを取得する。

## 3. 機能1: プロンプト生成(タブ①)【2026-11-02 改訂: 最終プロンプト固定版】

### 入力

- 参照画像: D&D/ファイル選択で1枚登録。プレビュー・差し替え・削除可能。メモリ上のみ保持(リロードで消える)。プロンプトには画像を埋め込めないため、「ChatGPTに参照画像も添付してください」という案内を常時表示する。
  - **「画像をコピー」「画像を保存」ボタン**(2026-11-07、追加修正指示書 第7弾 項目24): 参照画像の
    登録エリアに2つのボタンを置く(画像が未登録のときは両方無効化)。「画像をコピー」は
    `navigator.clipboard.write([new ClipboardItem({'image/png': blob})])`でクリップボードへ
    コピーし(JPEG/WebPはCanvas経由でPNGへ変換、元の解像度のまま縮小しない。
    `src/prompt/clipboardImage.ts`)、成功/失敗でトースト文言を出し分ける。「画像を保存」は同じ
    PNG形式でダウンロードする。プロンプトの「クリップボードにコピー」ボタンの隣にも、同じ動作の
    「画像をコピー」ボタンを並べる(どちらも参照画像の登録状況に連動して有効/無効が切り替わる)。
    `navigator.clipboard.write`・`ClipboardItem`に対応していないブラウザ(`file://`で開いた場合を
    含む)では、「このブラウザでは画像のコピーに対応していません。『画像を保存』を使ってください。」
    と表示し、コピーボタンを無効化する(保存ボタンは引き続き使える)。プロンプトをコピーした後の
    トーストは、参照画像が登録されている場合のみ「次は、参照画像もChatGPTに貼り付けてください。」を
    添える。参照画像は、これまでどおりlocalStorage・JSONには保存しない。
- 24行の入力表(No.固定、セリフ/状況の2列。セリフが左)。セリフ・状況の両方が未入力の行は警告するが生成は可能。
- 貼り付け: 次の3形式を自動判定して取り込む。
  1. `『セリフ』｜状況`形式(行頭が『で始まり』｜を含む行が過半数のとき)。
  2. `セリフ,状況`の2列CSV/TSV(ヘッダー有無自動判定)。
  3. 旧`お題,状況,セリフ`の3列形式(ヘッダーに「お題」があれば判定。お題の列は捨てて取り込む)。
- CSVテンプレートのダウンロード(`セリフ,状況`の2列)。
- 共通設定: キャラクター補足(任意)、追加指示(任意)の2項目のみ。書体・文字色・縁取り・背景色の設定は廃止(プロンプト本文を固定文化したため不要になった。docs/decisions.md参照)。
- 背景は透過で固定。「ChatGPTが透過PNGを返さず、白背景や市松模様の画像が返ることがある。その場合はタブ②で背景色モードに切り替える」旨を画面に案内する。
- 入力内容・共通設定はlocalStorageに自動保存(画像は保存しない)。プロジェクトJSONのversionは2。

### 出力

- プロンプト全文を読み取り専用テキストエリア(固定文部分/24行部分を薄い区切りで分けて表示。コピーされるテキストは区切りなしの全文)に表示、文字数表示、クリップボードコピー(トースト通知)。
- 「プロンプトを生成」の直前にサマリー表示(入力済み行数、セリフ/状況が空の行番号)。
- プロジェクトのJSON保存/読込(入力表+共通設定、versionフィールドあり。旧v1データはお題・書体等を捨ててセリフ・状況だけ引き継ぐ)。
- 個別再生成プロンプト(各行、backlog参照。未設計)。

### プロンプトテンプレート

ほぼ全文を固定文とし、可変なのは24行の内容(セリフ・状況)とキャラクター補足・追加指示のみ。詳細は `docs/prompt-template.md` を参照。

## 4. 機能2: 画像分割・書き出し(タブ②)【2026-11-02 改訂: 複数シート対応版】

タブ②は、同じ画面内で行き来する2ステップ構成。複数のシート画像(最大8枚)を読み込み、
スタンプ番号ごとにどのシートの同じ番号の枠を採用するかを選べる。

### 4.1 入力

- シート画像(PNG/JPEG/WebP)。想定1536×1024前後、最大4096px程度まで対応(超える場合は検出用に縮小コピーを使用、切り出しは元解像度)。
- 複数ファイルの同時ドロップ・追加に対応(最大8枚。超過分は警告して無視)。
- AIが背景透過PNGで出力した場合と、透過に失敗して白背景などで出力した場合の両方に対応する
  (画像ごとに自動判定+手動切替。4.2参照)。

### 4.2 ステップA: 読み込みと検出

シート画像がないとき、または「← 枠の調整に戻る」を押したときに表示する画面。画面上部にシートタブ
(サムネイル代わりの名前表示、表示名変更・削除・並べ替え)を置き、複数シートを独立して管理する。

- **透過画像の判定**(`split/mask.ts`): 読み込んだ画像のうち、透明に近い画素(alpha < 250)が
  全体の20%以上あれば「透過画像」と自動判定し、背景色推定を行わずalpha > しきい値(既定16)の
  画素を前景とする。そうでなければ従来どおり背景色推定+色差方式(白背景などへのフォールバック)。
  判定結果(「透過画像として処理中」/「背景色で処理中」)を画面上部に表示し、シートごとに
  手動で切り替えられる。偽の市松模様背景の自動除去は今回は対象外(docs/backlog.md参照)。
- 自動検出アルゴリズム(概要。詳細は`docs/architecture.md`を参照):
  1. 前景マスク作成(背景色推定→差分しきい値、または透過画像モードならアルファしきい値→連結成分ラベリングでノイズ除去)。
  2. グリッド境界検出(投影法。失敗時は等分割フォールバック)。
  3. セルごとのbbox(`Rect`)算出+警告フラグ(空セル・境界接触・サイズ異常)。
- 検出パラメータ(背景判定しきい値/前景判定しきい値/最小面積/検出方式/透過画像モード)は
  シートごとに持つ。新しいシートの初期値は、直前に開いていたシートの値を引き継ぐ。
- 検出結果エディタ: 枠の選択・移動・リサイズ・矢印キー移動・ズーム/パン(スペース+ドラッグ、またはホイールクリック+ドラッグ)、「枠を描き直す」「内容にフィット」「番号の入れ替え」「再検出」「枠の編集をリセット」。透過画像は白文字・白フチが見えづらいため、表示背景を市松/暗色で切替可能。
  - **リサイズハンドル**(2026-11-07、追加修正指示書 第6弾 項目22): 選択中の枠に、画面上で固定サイズ
    (10px四方)の白塗り+アクセント色縁のハンドルを8個(角4個+辺の中央4個)表示する。ズームしても
    見た目のサイズは変わらない。当たり判定は半径14px(画面px)に拡大し、枠が小さく辺の中央ハンドルが
    角と重なる場合は中央ハンドルを非表示にして角を優先する。ポインタの位置に応じてカーソルを切り替える
    (角=nwse-resize/nesw-resize、辺=ns-resize/ew-resize、枠内=move)。ホバー中のハンドルはハイライト
    表示する。Shift押下中のリサイズ(角ハンドルのみ)は縦横比を維持し、Alt押下中は中心を固定して
    拡縮する(Shift+Altの併用も可)。ドラッグ中は、枠の幅・高さ(px)を枠の近くに小さく表示する。
  - **枠外を暗くする**(既定ON、トグルボタンで切替): 選択中の枠の外側を薄く(20%)暗くし、切り出される
    範囲を分かりやすくする。
  移動・リサイズ・入れ替え・リセット・内容にフィット・矢印キー移動は、操作確定時(ドラッグ終了・ボタン押下・キー押下)に1手としてUndo/Redo履歴にコミットされる(`split/history.ts`。最大50手、Ctrl/Cmd+Z・Shift+Ctrl/Cmd+Z/Ctrl+Y、画面上のボタンでも操作可)。シート切り替え・再検出時は履歴を作り直す(持ち越さない)。
  「この枠で確定」の近くに「枠を変えていないスタンプの調整内容(補正・配置・消しゴムなど)は
  保持されます。大きく変えた枠は、切り抜きと消しゴムがリセットされます」という案内を表示する
  (2026-11-07、追加修正指示書 第6弾 項目23)。
- 「この枠で確定」を押すと、全シートの編集結果をまとめてステップBへ進める。ステップBから
  「← 枠の調整に戻る」(アクセント色の太枠、常に目立つスタイルでステップB上部バーの左端に配置。
  2026-11-07、追加修正指示書 第6弾 項目23)でいつでも戻れ、戻っても採用元シートの枠を変えていない
  スタンプの個別設定は保持する。戻ったときは、ステップBで選択していたスタンプと同じ番号の枠を
  ステップAで自動選択し(採用元シートが複数ある場合はそのシートのタブへ切り替える)、枠が余裕を
  持って見えるようにズーム・パンを調整する(`split/cameraFit.ts`)。
- シートを削除すると、そのシートを採用元にしていたスタンプは先頭のシートへ戻る(確認ダイアログ表示)。

### 4.3 ステップB: プレビューと微調整

左の調整パネル(固定幅、sticky)と、右のカードグリッド(既定5列、24枚)の2カラム構成。

- **Undo/Redo**: 採用元の切替・個別設定(補正・切り抜き・配置)・表紙設定・全体設定・一括操作など、
  このステップでの操作を1手としてUndo/Redo履歴にコミットする(`split/history.ts`、`ProjectState`の
  スナップショット方式。画像データは含めない。最大50手)。スライダーはドラッグ終了時(または
  数値入力の確定時)に1手、ボタン操作は押下ごとに1手。画面上の「元に戻す」「やり直す」ボタンに加え、
  Ctrl/Cmd+Z・Shift+Ctrl/Cmd+Z・Ctrl+Yのショートカットでも操作できる(文字入力中は発火しない)。
  シート一式が変わる操作(枠確定・設定JSON読込)では履歴を作り直す(持ち越さない)。

- **カード一覧**: 各カードはプレビュー画像(現在の調整を反映、書き出しと同じ`renderStamp`を使用)・ファイル名・PNG容量(デバウンスして算出、1MB超は警告色)・「選択」ボタン・表紙バッジ・採用元バッジ(シートが2枚以上のときのみ、S1/S2等)・個別設定済みドット・警告アイコンを持つ。
  個別設定済みドットは、採用元の切替だけでは付かない(採用元バッジで見分けられるため)。縁補正・縁フチ・
  切り抜き・拡大・位置の実際の値が初期値と異なる場合だけ付く(2026-11-03、追加修正指示書 項目11)。
- **確認用の背景切替**: 市松/指定色(プリセット6色+カラーピッカー+HEX入力)。既定は市松。プレビュー表示のみに影響し、書き出し画像(透過)には影響しない。設定はlocalStorageに保存。
  カラーピッカー(`<input type="color">`)は、プリセットの白等と見分けられるよう🎨の目印を添え、
  `aria-label`/`title`を「カスタム色を選ぶ」にする(2026-11-03、追加修正指示書 項目13)。
  カード自体の背景は常に透明で、グリッドに設定した確認用背景が選択中のカードも含め全カードで
  同じように見える(カード選択の強調は、背景の塗りではなく枠線〈二重線〉のみで行う)。カード内の
  文字色は、指定色モードでは背景の明るさ(相対輝度、`shared/color.ts: pickTextColor`)に応じて
  明るい/暗い文字を自動で切り替える。市松模様のときは常に暗い文字(2026-11-03、追加修正指示書
  第3弾 項目14。黒背景で白フチを確認する際、選択したカードだけ明るい背景が乗って確認できなく
  なっていた不具合の修正)。
- **選択中の拡大プレビュー**: 上部バーに、選択中の1枚を確認用背景の上に実寸〜2倍(最大260×240px)で
  表示する領域を置く。白フチやゴミ除去の残り具合を拡大して確認できる。選択中のカードの調整内容が
  変わるたびに連動して更新する(2026-11-05、追加修正指示書 第3弾 項目16)。
- **左の調整パネル**(選択中の1枚に適用。詳細は`docs/architecture.md`):
  - 採用元(シートが2枚以上のときのみ表示): 各シートの同じ番号の枠のサムネイルを並べ、クリックで切替(ラジオボタン式)。「全シートで比較…」ダイアログからも選べる。
  - 補正: 縁補正(-5〜+10px)、縁フチ(0〜16px)。縁フチはキャラクター・セリフ文字を含めた
    全体を1つの白フチ(#FFFFFF、エッジはなめらか)で囲む仕様で、文字領域だけ別幅にする機能は
    持たない(2026-11-03、修正指示書 項目8。docs/backlog.md参照)。既定値は0(AIがすでに白フチを
    描いた透過画像を前提とし、二重フチを避けるため)。スライダーには「AIがすでに白フチを描いている
    場合は0〜2px程度に」という案内文を表示する。背景色モードで縁フチ=0のときは、左パネルに
    「推奨: 縁フチを付けてください」という案内(アイコン色だけでなく文言でも示す)を表示する
    (フラッドフィルでAI自身の白フチが背景と一緒に消えやすいため)。
  - 消しゴム: 「手動で消す…」ボタンで全画面の編集ダイアログを開く(`split/eraseEditor.ts`)。
    キャラの一部や、ゴミ除去で消しきれない範囲を直接消したいときに使う。マスクは色を問わず、
    背景透過の直後・ゴミ除去の前に適用される(2026-11-06、追加修正指示書 第5弾 項目19)。詳細は
    4.3.1を参照。何か消してある場合、ボタンに「(編集あり)」を表示する。「この1枚をリセット」は、
    個別設定(補正・切り抜き・配置)に加えて消しゴムの編集も消えるため、確認ダイアログを表示する。
  - ゴミ除去(半透明のもや、0〜60%、既定0=OFF): AIが生成した透過PNGに残る、被写体周りの半透明の
    もや(白・灰色・暗い色を含む、ビネット・光彩・影の名残り等)を除去する。背景透過の直後に適用する
    (`export/ghost.ts: removeGhost`)。判定は色を問わず、次の3条件のみで行う(2026-11-05、追加修正
    指示書 第5弾 項目18。最優先の方針: 文字・キャラの白フチは絶対に消さない)。
    1. アルファがスライダー値(%)以下(半透明)である。
    2. その画素が「確かな前景」(アルファが`solidAlphaMin`〈既定200〉以上の画素。色を問わないため
       白フチ・文字・キャラのどれでも前景になる)の外側にある。
    3. 前景からの距離が「ゴミ除去の保護範囲」(`protectEdgePx`、0〜4px、既定1px)を超えている。
    被写体の内部(前景に囲まれて外周から辿り着けない範囲)は保護する。前景はアルファだけで判定する
    ため、本体から離れた位置にある不透明な白フチ・文字も、連結の有無に関係なく保護される。透過画像
    モード・背景色モードの両方で動作する。スライダーには「キャラクターの背景に残った半透明のもや
    (白・灰色・暗い色)を除去します。不透明な白フチや文字は消えません。黒背景で確認すると分かり
    やすいです」、保護範囲のスライダーには「文字や白フチが削れる場合は、値を上げてください」という
    案内文を表示する。全体設定にも両方の既定値のスライダーがあり、個別設定で上書きしていない
    スタンプに使う。
  - 切り抜き: 上/右/下/左(0〜枠サイズの40%)。採用元シートごとに別々に保持する。
  - 配置: 拡大(20〜300%、100%=安全領域にフィット)、横位置・縦位置(-150〜+150px)。採用元を切り替えても引き継ぐ。
  - 各項目はスライダー+数値入力、ダブルクリックで初期値に戻る。
  - 「表紙に設定」(常に1枚のみ、既定01番)、「この1枚をリセット」、「全体に適用…」(補正・配置の値を他23枚にコピー、項目を選択可。採用元・切り抜きは対象外)、「採用元をまとめて設定…」(すべて/奇数番だけ/偶数番だけ/空の枠・警告のある枠だけ、を指定シートにまとめて変更)。
  - 折りたたみ式「全体設定」: 出力サイズ/内側余白/縁フチの既定値/透過しきい値/feather/揃え/アップスケール許可。
    透過しきい値には「背景色モードでAIの白フチが消えてしまう場合は、この値を下げると消えにくくなる」
    という案内文を表示する。

#### 4.3.1 手動消しゴムの編集画面(`split/eraseEditor.ts`、全画面ダイアログ)

「手動で消す…」ボタンで開く。選択中スタンプの「背景透過の直後・ゴミ除去の前」の画像
(ステップAの検出枠+切り抜きに、フチ用余白を加えた範囲)を編集対象にする。元画像・マスクは
書き換えず、「完了」を押すまでは破棄できる(非破壊)。

- **表示**: 「作業中の画像」(編集対象)と「プレビュー: 最終結果」(ゴミ除去・縁補正・縁フチ・
  配置まで適用した、書き出しと同じ見た目)を左右に並べる。最終結果は、消しすぎて白フチや文字が
  消えていないかを確認するためのもので、ストローク編集中は更新せず、ストローク終了時にだけ
  再計算する(パフォーマンスのため)。
- **ツール**: 消しゴム(E)/復元(R)、ブラシサイズ(1〜100px、画面pxをズーム倍率で元画像pxへ
  変換)、硬さ(0〜100%、縁のなめらかさ)。Shift+クリックで直前のストローク終端から直線を引ける。
  ブラシは「消しゴム」が値を255側へ、「復元」が値を0側へ寄せる合成方式のため、同じストローク内で
  ブラシが重なっても不自然に濃淡が強まらない。
- **表示操作**: ホイールで拡大縮小、スペース+ドラッグ(または中ボタンドラッグ)でパン
  (ステップAの検出画面と同じ操作感)、`[`/`]`キーでブラシサイズ変更。
- **背景切替**: 市松/黒/白/確認用背景(現在のステップBの確認用背景と同じ色)。初期値は確認用背景。
- **消去範囲を表示**: チェックすると、「作業中の画像」側にのみ、消去量に応じた半透明の赤い
  オーバーレイを重ねる(透明になった部分は背景と区別しにくいため)。
- **Undo/Redo**: 1ストローク=1手(ドラッグ中はコミットしない)。画面内の「元に戻す」「やり直す」
  ボタンに加え、Ctrl/Cmd+Z・Shift+Ctrl/Cmd+Z・Ctrl+Yでも操作できる。「すべて元に戻す(リセット)」は
  確認ダイアログを表示してから、その1枚の消去をすべて元に戻す。
- **完了/キャンセル**: 「完了」でマスクを確定し、ステップBのUndo/Redo履歴にも1手として積む
  (編集画面内のストローク単位Undo/Redoとは別)。全画素が0(未編集)ならマスク自体を保存しない。
  「キャンセル」(またはダイアログのEscape)は変更を破棄する。

### 4.4 描画パイプライン(`export/renderStamp.ts`、プレビューと書き出しで共用)

1. 枠の切り出し(切り抜き適用後の範囲+フチ用余白。範囲外は背景として強制。背景色モードは不透明な背景色、透過画像モードは透明)
2. 背景透過(`export/alpha.ts`。背景色モードはフラッドフィル方式〈内部の白領域は保持〉、透過画像モードはAIが出力したアルファをそのまま使う)
3. 手動消しゴム(`export/erase.ts`、`applyEraseMask`。ユーザーが編集画面〈4.3.1〉で消した範囲の
   アルファを0にする。非破壊〈元画像は書き換えない〉。マスクはシート画像の絶対座標で保存し、
   切り出し範囲に合わせて位置を揃えてから適用する〈`alignEraseMaskToCrop`〉。2026-11-06、
   追加修正指示書 第5弾 項目19。設定JSONへの保存/読込は`split/eraseMaskCodec.ts`で、
   1チャンネルPNG+Base64のdata URLとして行う〈2026-11-06、項目19-c〉)
4. ゴミ除去(`export/ghost.ts`、半透明のもやを除去。2026-11-05、追加修正指示書 第3弾 項目15。詳細は4.3参照)
5. 縁補正(`export/edge.ts`、アルファの収縮/膨張)
6. 配置(`export/layout.ts`、安全領域に収まる倍率を100%とし、拡大率・オフセットを適用。はみ出しは許可するが警告を出す)
7. 縁フチ(`export/outline.ts`、出力解像度でアルファ膨張、配置後に適用)。はみ出し警告(`computeStampWarnings`)は
   縁フチで膨張する分も含めて判定する(縁フチだけでキャンバス外に出る場合も、同じ警告を使う)。
8. 解像度不足バッジ表示。実効拡大率に応じて2段階にする(2026-11-03、追加修正指示書 項目12。
   しきい値は`shared/lineSpec.ts`の`UPSCALE_CAUTION_THRESHOLD`(1.3)・`UPSCALE_WARNING_THRESHOLD`(1.6)):
   - 注意(黄色の⚠): 1.3倍超〜1.6倍以下
   - 警告(赤色の⚠): 1.6倍超
   カードのツールチップには実効拡大率(例: 「約1.4倍に拡大」)と、「注意:」「警告:」の文言を
   先頭に付ける(色だけに頼らない)。書き出し前の検証では、警告(1.6倍超)は番号つきで警告を出し、
   注意(1.3〜1.6倍)は件数のみ案内する(書き出し確認ダイアログの件数カウントには含めない。
   本当に危ない警告が埋もれないようにするため)。
9. 出力サイズは偶数に丸める

背景処理(透過画像モード/背景色モード)は、そのスタンプの採用元シートの設定に従う。

### 4.5 設定データ

`ProjectState`(`split/types.ts`、version 2)として、シート一覧(`sheets: Sheet[]`。検出枠・検出設定・
名前。画像データ本体は含まない)、スタンプごとの個別設定(`stamps: StampSetting[]`。採用元シートID・
補正や配置の調整値・採用元シートごとの切り抜き量・採用元シートごとの消去マスク)、全体設定、表紙番号、
プレビュー背景設定を保持する。JSON保存/読込可。読込時は、保存されているシート名と現在読み込み済みの
シート名を突き合わせる(ファイル名・サイズでの自動対応づけ+手動割り当てUIは今回は簡易化。
docs/decisions.md参照)。旧version 1(単一シート)の設定JSONを読み込んだ場合は、シート1枚のversion 2
として自動変換する(消去マスクは存在しないため常に空)。

消去マスク(`eraseMaskBySheet`)は、`Uint8ClampedArray`をそのまま保存すると巨大になるため、
`split/eraseMaskCodec.ts`で1チャンネル(グレースケール)PNG+Base64のdata URL(`png`)と座標メタ情報
(`x`・`y`・`width`・`height`、シート絶対座標)に変換してから保存する(2026-11-06、追加修正指示書
第5弾 項目19-c)。すべて0(未編集)のマスクは、キー自体を保存しない。読込時、マスクが存在しない場合は
エラーにせず空のまま扱う。デコードしたPNGのサイズが保存されていた`width`・`height`と一致しない場合は
(壊れた/想定外のデータ)、そのシートぶんのマスクだけを破棄して読み込みを続行し、「読み込めなかった
消しゴムのマスクがN件あります」というトーストで知らせる。

### 4.6 書き出し

`stamps_YYYYMMDD_HHMM.zip`(01.png〜24.png + main.png[240×240] + tab.png[96×74]、タブ画像出力は既定ONのチェックボックスで切替可)。main/tab画像は表紙スタンプの採用元シート・調整結果を引き継いで生成する。書き出し前検証(サイズ上限・偶数・容量1MB・24枚揃っているか・はみ出し警告・採用元シートが見つからないスタンプがないか)。「採用元一覧(sources.txt)も同梱」オプション(既定OFF、番号→採用元シート名の一覧をZIPに含める)。個別PNG保存、設定JSON保存/読込。

#### 書き出しZIPの自動検証(`scripts/verify-zip.mjs`、追加修正指示書 第7弾 項目25)

ツール本体の書き出し前検証とは別に、書き出し済みのZIPファイルを独立したNode製CLIスクリプトで
機械的に検査できる(`npm run verify:zip -- path/to/stamps_YYYYMMDD_HHMM.zip`。`--json`で機械可読の
出力)。依存は`jszip`とNode標準モジュールのみ(PNGのデコードは自前実装、`src/shared/lineSpec.ts`の
定数を`npm run sync:line-spec`で`scripts/lineSpec.generated.json`へ同期してから使う。`verify:zip`は
この同期を自動で行う)。

検査項目(NG=1件でもあれば終了コード1、注意のみなら0):

| 項目 | 内容 | 判定 |
|---|---|---|
| ファイル構成 | 01.png〜24.png・main.png・tab.pngがそろっている。余分なファイルは情報として表示 | 不足=NG |
| スタンプのサイズ | 各画像が最大370×320以下 | 超過=NG |
| 偶数 | 幅・高さが偶数 | 奇数=NG |
| main.png / tab.png | それぞれ240×240・96×74ちょうど | 相違=NG |
| 容量 | 各PNGが1MB以下 | 超過=NG、900KB超=注意 |
| PNG形式・透過 | PNGとして読める、アルファチャンネル(またはtRNS)を持つ | 不正=NG |
| 完全に空 | 全画素が透明 | NG |
| 外周の透明 | 画像の最外周(1px)がすべて透明 | 不透明が混じる=注意(被写体が端に接している可能性) |
| 透明画素の割合 | 全体に対する透明画素の割合 | 5%未満=注意(背景が残っている可能性) |
| 半透明のもや | アルファ1〜30%の画素の割合 | 3%超=注意(黒背景でもやに見える可能性) |
| 余白 | 被写体(アルファ>0)の外接矩形と画像端の距離 | いずれかの辺が4px未満=注意 |
| 重複 | 同じ内容(ハッシュ一致)のPNGが複数ある | 注意 |
| 合計 | ZIP内の合計サイズ | 情報 |

ピクセル検査(完全に空・外周の透明・透明画素の割合・半透明のもや・余白)は、非インターレース・
ビット深度8・カラータイプ4(グレー+アルファ)/6(RGBA)のPNGのみ対応する。それ以外の形式
(カラータイプ0/2/3や、ビット深度8以外・インターレースPNG)は、ピクセル検査を「情報」として
スキップし、失敗扱いにはしない(本ツール自体が書き出すPNGは常にカラータイプ6のため、実運用では
通常すべて検査対象になる)。CRC32の検証は行わない(改ざん検知が目的ではないため)。

## 6. UI要件

- 1ページ構成、2タブ(「① プロンプト作成」「② 画像分割・書き出し」)。
- 日本語UI、システムフォントのみ(外部フォント禁止)。
- トースト・処理中表示・エラーメッセージを日本語で表示。
- 空状態には次のアクションの案内を表示。
- キーボード操作可能、ボタンにラベル付与、色だけに依存しない。

## 7. 非機能要件

- 外部ネットワーク通信なし(CDN・外部フォント・アナリティクス禁止)。
- 画像処理コアはDOM非依存の純粋関数(`{width, height, data: Uint8ClampedArray}`入出力)。
- 依存パッケージは vite / typescript / vitest / jszip / eslint系(typescript-eslint) / prettier のみ。
