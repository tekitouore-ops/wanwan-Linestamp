# 設計判断ログ

見出しは「日付 + 決定事項」、本文に理由を書く。判断が変わった場合は打ち消さずに新しい項目を追記する。

## 2026-11-02: Vite + TypeScript(フレームワークなし)採用

React/Vueなどは使わず、素のTypeScript + DOM操作で実装する。理由:

- 依存を最小限にする方針(許可パッケージ: vite, typescript, vitest, jszip, eslint系, prettierのみ)と合致する。
- UIは「2タブ・フォーム・Canvas描画」中心で、フレームワークの状態管理機構が必須な複雑さではない。
- 画像処理の中核を純粋関数(DOM非依存)に分離する設計方針と、フレームワーク非依存のDOM操作は相性が良い。

## 2026-11-02: 白フチはAIに任せずツール側(outline.ts)で付与する

プロンプトの「白フチの指示」は既定OFFとし、`src/export/outline.ts` で描画パイプライン側に生成する。理由:

- 背景色が白の場合、AI生成画像上で「キャラの白フチ」と「背景の白」が視覚的に区別できず、自動検出(mask.ts)の精度が落ちる。
- ツール側で透過処理後のアルファチャンネルを基準に膨張させれば、フチの太さ・色を安定して制御できる。
- ユーザー設定で白フチをプロンプトに追加したい場合のオプションは残すが、既定は無効。

## 2026-11-02: 自動検出は投影法 + 等分割フォールバックを採用

`src/split/gridSplit.ts` の境界検出は、前景マスクの縦横投影から「空の帯」を探して境界を決める投影法を基本方針とし、検出に失敗した場合は等分割にフォールバックする。理由:

- AI生成シートは厳密なグリッドにならず(列位置が行ごとにずれる等)、固定座標での単純等分割だけでは枠がずれる。
- 投影法は前景・背景の分布から境界を推定できるため、多少のずれに対して頑健。
- 完全に検出が失敗するケース(背景とキャラの色が近い等)もあり得るため、確実に動作する等分割フォールバックを用意し、UIで切り替え可能にする。

## 2026-11-02: TypeScriptは7系ではなく6.0系を採用

npm上の `typescript` の最新版は7.0系だが、ESLint用の `typescript-eslint` パッケージの
peerDependencies が `typescript: ">=4.8.4 <6.1.0"` までしかサポートしていないため、
`typescript@^6.0.3`(6.1未満で最新の安定版)を採用した。7系がtypescript-eslintでサポートされ次第、
追従を検討する。

## 2026-11-02: lineSpec.ts にLINE規格値を集約し、将来のセット枚数拡張に備える

本ツールはLINEスタンプ24枚セットのみを対象とするが、`lineSpec.ts` には8/16/24/32/40等のセット枚数候補やメイン画像・タブ画像のサイズ定数も保持しておく(未使用でも型・定数として定義)。理由: 将来拡張(docs/backlog.md)時に、規格値の変更箇所を1ファイルに限定できるようにするため。

## 2026-11-02: CSV/TSV貼り付けの区切り文字・ヘッダー判定は簡易ヒューリスティックとする

`src/prompt/csv.ts` の `parseRows` は、(1)先頭行のタブ数とカンマ数を比較して多い方を区切り文字とする、
(2)先頭行のいずれかのセルが「お題」「状況」「セリフ」のいずれかと完全一致すればヘッダー行とみなす、
という単純な方式を採用した。理由:

- Excel/Googleスプレッドシートからのコピーはタブ区切り、CSVファイルからの貼り付けはカンマ区切りになることが多く、先頭行の文字数比較で実用上十分に判別できる。
- ヘッダー有無の自動判定は完全ではないが、想定される日本語ヘッダー(お題/状況/セリフ)に限定することで誤判定の可能性を下げている。
- 判定を誤った場合もアプリがクラッシュすることはなく、ユーザーが表を見て手直しできるため、致命的な問題にはならない。

## 2026-11-02: 個別再生成プロンプト機能はPhase 2では見送り

元の指示で「余力があれば実装する」とされていた、各行ごとの「この1個だけ再生成するプロンプトを作る」機能は、
Phase 2では実装しなかった。理由: 24行表・CSV貼り付け・共通設定・プロンプト生成・JSON保存読込・localStorage自動保存という
必須要件を優先し、Phase 2の受け入れ基準(テンプレート通りのプロンプト生成とテスト通過)を満たすことを優先したため。
テンプレート自体は `docs/prompt-template.md` に設計済みのため、余力があるタイミングで追加実装する(docs/backlog.mdにも追記)。

## 2026-11-02: 未入力行の警告は「お題」「状況」のみを対象にする

`findIncompleteRowNumbers` は、24行のうち「お題」または「状況」が空の行を警告対象とし、「セリフ」は対象外とした。
理由: 元の指示で「セリフ」列は任意(空欄なら文字なし)と明記されている一方、「お題」「状況」は推奨項目とされているため。
