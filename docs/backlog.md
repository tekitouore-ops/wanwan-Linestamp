# バックログ(将来拡張の候補)

本ツールの現行スコープ外で、将来検討する拡張候補。優先順位は未定。

- **12枚×2シート方式への対応**: 1枚のシートに24個詰め込むと1個あたりの生成解像度が低くなるため、12枚×2シートに分けて生成解像度を上げる方式。`cols`/`rows`パラメータは既に内部で可変にしてあるため拡張しやすい想定。
- **クロマキー方式**: 背景色を緑などの特殊色にして、色キー的な透過処理の精度を上げる方式。現行は白背景+連結領域フラッドフィル方式。
- **個別スタンプの再生成→差し替え**: 1個だけ出来が悪い場合に、個別再生成プロンプト(未設計。下記「個別再生成プロンプト(タブ①)」参照)で作った画像を、シートの該当枠にはめ込んで差し替える機能。
- **アニメーションスタンプ対応**: APNG形式、フレーム数・タイミングの規格に対応する拡張。本ツールの静止画パイプラインとは別の検討が必要。
- **GitHub Pagesでの公開**: Phase 5で `deploy.yml` を用意する。公開設定(Settings → Pages → Source → GitHub Actions)はユーザー側の手動作業。
- **Web Workerへの処理オフロード**: 検出・フラッドフィル処理が重い場合に、UIスレッドのカクつきを避けるためWorkerに逃がす。現行はメインスレッドで実装し、問題が出た場合に対応する想定。
- **Undo/Redo**: 検出結果エディタでの枠編集に対するUndo/Redo(Phase 3で余力があれば先行実装)。
- **個別再生成プロンプト(タブ①)**: 各行に「この1個だけ再生成するプロンプトを作る」ボタンを追加する。2026-11-02の仕様変更でプロンプト本文を固定文化したため、短縮版テンプレートは未設計(着手時に`docs/prompt-template.md`へ追記する)。Phase 2では見送った(docs/decisions.md参照)。
